How the branding system actually works.

No jargon — just the shapes, the screens, and the flow of data from a business owner's slider to a visitor's browser.

Three ideas, and that's most of it

Everything else in the system is built from these three pieces.

✎
Draft
What the owner is editing right now. Not shown to visitors yet.

Snapshot

What happens when an owner edits their theme

This is the "editing" side — nothing here touches the live site yet.

EDITING FLOW
1
Owner drags a slider or picks a color
In their settings screen — a control panel you build for them.
2
It's saved as a Draft
Stored in the database, just for that one business. Nobody else sees it.
3
They see a live preview
Their screen updates instantly, so they know what it'll look like.
4
They click "Publish"
Only now does anything change for real visitors.

What happens when a visitor loads the site

This is the "visiting" side — it never re-does any work, it just looks something up.

VISITING FLOW
1
A visitor opens the tenant's website
e.g. acme.yourplatform.com
2
The server checks which business this is
From the web address, the same way it already routes to the right tenant's content.
3
It grabs that business's current Snapshot
Already fully built — no calculation happens here, just a quick lookup.
4
The page loads already branded
Right colors from the very first paint. No flicker, no flash of the wrong brand.

Semantic colors are locked on purpose — an owner repainting "error" to match their brand would make error states stop reading as errors. Font choice is a curated list even here, never free text, for licensing reasons as much as design ones.

How a developer sets this up

The developer decides which tier each field gets, once, in a small config file. Nothing fancier than this.

// This is the developer's config — decided once per product, not per tenant
{
  "companyName":    { "tier": "direct" },
  "logo":           { "tier": "direct", "type": "asset", "variants": ["light", "dark"] },
  "brandColor":     { "tier": "direct" },
  "semanticColors": { "tier": "locked" },
  "headingFont":    { "tier": "guided", "type": "select", "options": [
                      { "label": "Inter",          "value": "inter" },
                      { "label": "Space Grotesk",  "value": "space-grotesk" },
                      { "label": "IBM Plex Sans",  "value": "ibm-plex-sans" }
                    ] },
  "radius":         { "tier": "guided", "type": "select", "options": [
                      { "label": "Sharp", "value": "0.125rem" },
                      { "label": "Soft",  "value": "0.5rem" },
                      { "label": "Round", "value": "1rem" }
                    ] },
  "density":        { "tier": "guided", "type": "select", "options": [
                      { "label": "Compact",     "value": "0.875" },
                      { "label": "Comfortable", "value": "1" }
                    ] },
  "elevation":      { "tier": "guided", "type": "slider", "min": 0, "max": 100 },
  "advancedTokens": { "tier": "raw" }
}

Eight fields shown, all live at once — an illustrative subset. The reference brand kit in guideline §33 has thirteen, adding bodyFont, neutralTone, buttonStyle, supportUrl and emailSenderName. Nothing in the schema limits how many are active; this mockup is trimmed to fit on one screen.

Notice semanticColors is locked by the developer, not by the owner's choice — an agency-tier profile would flip just that one entry to direct, same schema, different profile row (§17). Select options are { label, value } pairs, never bare strings: the label is what the owner reads, the value is what lands in the token.

Plain-language glossary

Site
The thing that has a theme — one domain, one brand. This is what everything in the database is keyed by.
Account
A login. Owns one or more sites — an agency managing ten client brands is one account with ten sites.
Tenant
The everyday word for a business using your platform. In practice it means one site; the code always says "site".
Profile
A reusable template of tier settings — "free", "pro", "agency". Copied into a site when it's created; the two are independent afterwards.
Draft
The in-progress version of a theme. Only the owner sees it.
Snapshot
A saved, frozen theme. Safe to show real visitors.
Publish
Turning a draft into a new snapshot, and making it the live one.
Rollback
Switching back to an older snapshot, instantly, if something looks wrong.
Adapter
A small piece of code that connects the core system to one specific tool — like shadcn, or Prisma, or Lucid.
Tier
How much freedom an owner gets on one field — locked, guided, direct, or raw.
